# S011a-001: three hosted one-hour fault/recovery runs

**Engineering outcome: 3 of 3 runs clean.** Each hosted Luna run took a
registered runtime kill. The supervisor recovered it automatically under the
ADR-0021 identity pin, the run reached its 3600-second deadline, and the
archive verifies. The S011a exit criterion (three consecutive clean runs, each
with at least one recovered fault) is met.

**Main limitation:** every kill landed during quiet idle. No live run recovered
from a crash while the model was active, so no provider request was replayed
live. That path is covered only by fake-provider tests. See
[Limits](#limits).

Registration: [S011a-001](registrations/S011a-001.md). Simulation `1bc219a`,
owner allowance recorded before launch. Runs were sequential, one at a time,
and each was classified before the next was launched.

## Limits

- **Active-phase recovery is not exercised live.** Luna went quiet within
  4.4–5.8 minutes, so all three registered kills, including the earliest at
  300 s, hit idle. Several paths are tested only with fake providers:
  - killing the runtime during a paced wait or an in-flight provider request;
  - replaying model steps since the checkpoint;
  - counting a replayed request against the ceiling;
  - the pin surviving a live reply after resume.

  A future registration should choose a kill time inside the observed active
  window, for example 120 s, or a step-based trigger.
- **Crash event wording.** The crash's `error` event says `"recoverable":
  false`, and the recovery that follows is recorded separately. The field
  describes the failed segment, not the run. This is existing behaviour, and it
  was left unchanged during the frozen campaign.
- **Identity limits.** Identity is a provider-reported version string, not an
  attestation (ADR-0021).
- **Not tested here:** host sleep, reboot and power loss (S011b), Linux, and the
  container tier.
- **Behaviour cannot be generalised:** one prompt, low effort, one quiet
  treatment, n = 3, with no comparison.

## Next

S011b (twelve hours) requires the owner's power and update arrangements, a
registered sleep/resume, and a new allowance. Hosted runs face an additional
limit: a 12-hour run may cross ChatGPT 5-hour or weekly usage windows. A usage
refusal ends a hosted run by design. S011b also needs a decision about the idle
profile: at most about 6 minutes of activity per hour has been observed so far.

## Close-out (2026-11-16, strategic reset)

The owner directed a strategic reset
([ADR-0022](../decisions/ADR-0022-strategic-reset-habitat.md)). This section closes
S011a and the preparatory test programme. No run was repeated, replaced or
extended, and no hosted request was sent while closing out.

- **Completed vs failed.** All three runs completed: each reached the 3600 s
  deadline with an intact archive. **No unexpected failure occurred.** The only
  failures in the record are the three **registered** runtime kills. Each one
  appears as one `error` event ("the agent runtime exited unexpectedly (status
  1)") and one `running → failed` segment transition, immediately followed by
  `recovering → running`. The runtime stderr logs are empty. There were no
  provider errors, retries, refusals or identity changes.
- **Did registered failure and recovery work?** Yes, for crashes during idle:
  1 fault, 1 restart, the correct checkpoint, the idle state restored, the pin
  recorded, and running again within 2 s in every run. Recovery during active
  model work was not exercised live (KI-31).
- **What the inhabitant did.** In each run it checked the workspace, memory and
  the clock, then replied three times in a row that nothing needed doing and
  went quiet: at 4.4, 5.7 and 5.7 minutes.
- **Capabilities used.** Only `workspace.list`, `memory.list` and `time.now`,
  through search/describe/invoke. Nothing was created, computed or preserved:
  the workspaces are empty and no memory database exists.
- **What was learned.**
  - *About the infrastructure:* hosted supervision, pacing, ceilings, identity
    pinning and crash recovery work end to end.
  - *About the inhabitant in this world:* under prompt C, low effort and the
    quiet policy, `gpt-5.6-luna` treats an empty, mostly utilitarian world as a
    waiting room. It looks around, finds no task or object worth acting on, and
    stops. S011p showed the same pattern, apart from two status-note writes.
  - This cannot separate the model's disposition from the world's poverty. The
    world offers nothing to discover, build or run, so the result is evidence
    about the *environment* as much as about the agent. It motivates the
    Habitat programme.

The preparatory test programme (S011b, S011c, comparison campaigns and
repeated capability benchmarks) is closed for active development. Its records
stay as written.
