# S020b — offline references and procedural audiovisual work

Completed 2026-11-16 after the owner's `Run next session` accepted the S020b
handoff. This scoped work includes reference acquisition and contained FFmpeg
provisioning. No model download/inference, host install/settings change or full
inhabitant simulation occurred. S012 records and all old images/world fixtures
are unchanged.

## Delivered

Habitat **1.2.0**, 25 capabilities, adds library.search/read and an immutable
`library/` directory. Builder validates UTF-8 text/CSV, simple relative filenames,
catalog version/fields, unique ids, source hashes, notices and per-file/total
size limits before packaging. Files are copied byte-for-byte and join the world
digest. Capability inputs are source ids and bounded queries/ranges, never URLs
or arbitrary filenames. Results retain citations, upstream revision, licence,
source SHA-256 and line numbers. No writable index, network or embedding model.

The initial genuine reference set is:

- Python 3.12.10 tutorial, *More Control Flow Tools* (PSF terms; original licence
  included), from the pinned upstream release;
- SymPy 1.14.0 introductory calculus tutorial and SciPy 1.18.1 scientific
  integration tutorial (BSD notices retained), from their upstream release tags;
- UCI Iris botanical measurements, 150 CSV rows (CC-BY-4.0, DOI
  `10.24432/C56C76`); a header is added and trailing blank lines removed,
  numerical rows unchanged. This adaptation is attributed explicitly.

Original documentation source text/RST is retained, not executed or rendered as
active content. All URLs, citations, licences/notices and hashes are in the
catalog. It is a small useful starting library, not a general book collection.

The new local image config ID is
`sha256:a0fb028f8e686c80e8c317b88570fc0bd61878be2b0c267a3a14fed27e341efb`.
It derives from the existing S020a image, adding Debian FFmpeg/ffprobe
`7:7.1.5-0+deb13u1`. Installed package inventories, build options, scientific

build enables GPL and does not enable nonfree components. Disk size is
1,495,645,879 bytes, not a RAM measurement. Runtime still never pulls images.
Image layers and raw build logs are not committed or publicly published.

Python programs can generate images/GIF, synthesize/mix PCM audio, mux frames
and sound to WebM, trim/filter video, extract frames and inspect ffprobe/PCM/
pixel outputs. General Python/FFmpeg programs supply this freedom; no one-off
render framework or prescribed inhabitant task is introduced. The existing
60 s Python maximum, 90 s outer timeout, explicit cgroup/quota grants and
50 MiB artifact cap remain. Old experiment limits/profiles are not raised.

Window adds independent PCM WAV and VP8/VP9 WebM recognition, native controls
without autoplay, bounded GET/HEAD streaming and one byte range. MIME comes
from container/header checks, never the filename or agent metadata. Unsupported
containers/codecs, malformed headers, excessive sizes/durations/dimensions and
invalid/multiple ranges are refused. Its source still opens files only through
open_readonly in rb mode, writes nothing, starts no converter and contacts no
service. CSP remains strict with media-src self and nosniff; active artifacts
remain inert text. Browser decoding is separate from bounded header recognition,
which does not certify an arbitrary compressed bitstream.

## Limits and next

This verifies small CPU procedural artifacts and reference retrieval on the
existing Windows/WSL machine. The library is intentionally small; RST syntax
and relative cross-references remain source text. Long/high-resolution media
and every FFmpeg feature are not certified. Audio analysis is numeric/structural;
neural perception/generation and delegation remain absent. No claim of autonomy
or cognitive continuity follows. No full Simulation suite was run because its
whole-run fixtures conflict with the v2 no-inhabitant-run instruction; relevant
direct component checks were used. Window's full suite ran.

S020 (phase 1) is complete. **S021**, optional local assistants and visual
creation, is next. A future real Lunar experiment still requires a separate
explicit owner decision after useful Habitat v2 completion.
