# S017: lawful persistent field phenomena

This is a scripted engineering demonstration, not an autonomy experiment. No
model inference, hosted spending, model download or system change was used.
The [design note](../PHENOMENA_V1.md) was written before implementation; the
supervisor boundary is recorded in [ADR-0024](../../decisions/ADR-0024-supervisor-phenomena.md).

## Delivered

Habitat **0.4.0**, twenty capabilities, content digest
`be37094fad7c256f9216e3feb6ffd65b16c88dd0c8812a3a555d84cd90ab8780`.
Two builds have the same digest; verification and all twenty self-tests pass.
All 67 generated Simulation fixture files are byte-identical to Builder output.
The three new Builder self-tests use a labelled unavailable fake, not simulated
observations. Rule source and private state are not bundled into the release.

The field is six by six, with bounded water/activity values and held local
drive controls. `world.observe` reads it, `world.act` changes one drive, and
`world.advance` evolves explicit simulation ticks. There are no scores, tasks,
target patterns or reward function. All equations execute as fixed code in the
supervisor; calls contain validated data only. The container world can observe
or lawfully intervene, but cannot directly rewrite state or inspect rule source.

Experiment extension `"phenomena": {"seed": 41}` enables the fixed service.
Missing configuration hides it, and permission/allow/deny checks still apply.
Each private-pipe request must match one outstanding recorded call, including
demonstrations; mismatches and duplicates are refused. The supervisor records
and syncs each candidate transition before commit and acknowledgement.

Private state joins the existing protected checkpoint component. The supervisor
overrides worker-supplied lookalikes and removes private state from worker
resume data. `ols verify` replays accepted operations with the versioned engine,
checks public results/state hashes and compares retained checkpoint state.

## Preserved demonstration

Simulation configuration: `experiments/habitat/s017-demo.json`.
Archive under the configured data root:
`runs/s017-demo/run-20261116t105733z-7010e6`.

1. Discover field observation and read its interface documentation.
2. Observe the initial field, then set drive 3 at site (2,2).
3. Advance four ticks, operator-pause after step five and verify the archive.
4. Resume and observe the same field without advancing it.
5. Set that drive to zero, advance eight more ticks, observe again and run the
   observation demonstration without changing the field.

Result: **completed**, 88 events, ten successful tool results, final tick 12.
Archive integrity and deterministic replay both pass; the pre-pause log remains
an exact prefix. Site (2,2) starts with water 422/activity 19. At tick 4 it has
water 457/activity 24; the same-seed, no-intervention control calculation gives
water 390/activity 23. At tick 12, after removing the drive, the demonstrated
site has water 368/activity 28. The unit/integration checks also observe spatial
effects in a neighbouring site. These are consequences of fixed scripted
interventions, not evidence of an agent independently investigating anything.

The preserved run used the supervisor API and archive verification at each
boundary. Equivalent reproduction commands from Simulation:

```text
uv run ols run experiments/habitat/s017-demo.json --pause-after-steps 5
uv run ols verify <archive>
uv run ols resume <archive>
uv run ols verify <archive>
```

## Engineering evidence

Twenty-two new Simulation tests pass with live containers required. They cover
a frozen seed vector, hand-calculated synchronous transport and torus neighbours,
bounds, no-op reads, isolated result copies, invalid input without effects,
tick limits, damaged private state, record-sync failure before commit,
uninterrupted versus paused/resumed equivalence, journal tampering, workspace
forgeries, sandbox source/state isolation, opt-in, deny lists and invalid
configuration. A hostile worker test checks unmatched/mismatched/duplicate pipe
requests, private-state exclusion from resume data and refusal of a worker's
forged private checkpoint field.

A separate real-worker crash test exits after a recorded advance to tick 3
but before the complete-step barrier. The last protected checkpoint is tick 0.
Resume restores that checkpoint, repeats the abandoned advance and ends at
tick 3, not 6. All earlier observations remain; replay validates both segments
and the explicit recovery reset. This is checkpoint rollback, not an
exactly-once crash claim.

Nine new Builder tests check data-only manifests, explicit unavailable fakes,
complete available outputs and refusal of invalid controls before service use.
Full regression results are recorded in `docs/roadmap/state.json`. An initial
build refused a duplicated `observe` keyword; it was corrected before a release
was written. Initial lint found two long lines in the hostile-worker fixture;
they were reformatted. No behaviour assertion was weakened or test skipped.

## Limits and next step

This is an abstract finite integer system, not a validated ecological model.
Simulation time advances only by explicit calls, to a total tick bound of
1000000. Crash recovery can roll back post-checkpoint effects while retaining
their records. Large/long-duration replay cost and Linux-host execution are
unmeasured. No cross-run field continuity, real-time scheduling, graphics,
other agents or new privileges were added. Next is S018, time and continuity.
