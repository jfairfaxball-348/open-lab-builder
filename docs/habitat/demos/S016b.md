# S016b: validate and reuse a sandboxed self-made tool

This is scripted engineering acceptance, not evidence of autonomy. No model
inference or hosted allowance was used. S016a supplied procedural notes;
S016b supplies executable tools without changing their sandbox privileges.

## Implemented

Habitat **0.3.0**, seventeen capabilities, content digest
`dbab97a3cc5f7a35a1586b0e2bd8073f0d4213d928ffaf18ad0513d0b452231b`.
Two Builder builds (local output and published release) have identical digests
and pass all seventeen self-tests. The generated Simulation fixture is copied
from the release. Builder's `tools.create` self-test is an explicitly
non-registering fake: it checks the interface and never executes agent source.
Real validation runs only through Simulation's container sandbox.

`tools.create` accepts an agent-written workspace `.py` file defining
`run(arguments)`, documented input/output schemas and up to five exact examples.
The runtime reads source as bounded data. Every example executes through the
existing `python.run` capability in a fresh container. Schemas, actual outputs
and expected values must agree before any registration is installed.

Registrations have `agent.<slug>` ids, generated capability manifests,
`origin: agent`, the infrastructure-assigned run id and a SHA-256 of the entry
source. They are searchable, describable, demonstrable and invocable through
the existing discovery interfaces. Execution results include provenance and
source digest in recorded extensions. Source, definition and digest live in
protected runtime/checkpoint state; workspace manifests cannot create or
replace a registration. New registrations require new ids.

The frozen experiment must explicitly enable `agent_created_tools`, grant
subprocess permission and use a container world containing both `tools.create`
and `python.run`. Both the target and runner remain subject to permission and
allow/deny checks. Disabled tools are hidden from discovery. There is no
process-tier, network, GPU, models or package-installation path.

## Preserved demonstration

Simulation configuration: `experiments/habitat/s016b-demo.json`.
Archive under the configured data root:
`runs/s016b-demo/run-20261116t102236z-38fb65`.

1. Search for reusable tool creation and describe `tools.create`.
2. Write `double.py`, which returns twice its integer argument.
3. Create `agent.double`, validating the example `3 -> 6` in the sandbox.
4. Operator-pause after the fourth step; verify the archive; resume the same run.
5. Replace `double.py` with code that would raise an exception if executed.
6. Rediscover `agent.double`, inspect its manifest and invoke it on `7`.
7. Observe `14` from the pinned entry and re-run its demonstration (`3 -> 6`).

Result: **completed**, 77 events, nine successful tool results, archive intact.
The pre-pause event log remains an exact prefix after resume. Source digest:
`88c1f71ab92757bc6b2adbc059c0f1fa0787f2967720652d9d1b4d3ae6d01b5b`.
Run and resume used the supervisor API, with archive verification at each
boundary. Equivalent reproduction commands from Simulation:

```text
uv run ols run experiments/habitat/s016b-demo.json --pause-after-steps 4
uv run ols verify <archive>
uv run ols resume <archive>
uv run ols verify <archive>
```

## Tests and limits

Twenty-one new Simulation tests pass with
`OPEN_LAB_REQUIRE_CONTAINER=1`. Real-container cases cover pause/resume,
source replacement, discovery/provenance, exact demonstration replay, wrong
example values, wrong output types, exceptions, timeouts, extra stdout,
truncation, and confinement during validation and later invocation. Unit cases
cover duplicate/Builder/meta-tool ids, runner/target permissions and opt-in,
source traversal/reserved names/hard links/junctions, entry size limits,
schema references/regex/invalid forms/depth/size, capacity, bad example data,
tampered checkpoint source and launch refusal without subprocess permission.
Two new Builder tests verify the non-executing self-test and closed creation
interface. A related 92-test Simulation regression subset also passed.

Initial lint checks found two long source lines and an unused test import;
these were corrected. No failing behaviour assertion was weakened or skipped.
Full regression results are recorded in `docs/roadmap/state.json`.

Only the entry source is pinned. Inputs, workspace data and imported workspace
modules remain mutable; successful examples are not general correctness or
safety proofs. Programs retain the existing container limits and five-second
inner execution limit. The service bounds source to 32000 bytes, schemas and
argument/result JSON to 16000 bytes, five examples, sixteen registrations,
schema depth eight and 128 nodes. The manifest documents the supported schema
subset. Failed validation may leave example workspace side effects; it never
registers the tool. No cross-run sharing is implemented.

Native execution was Windows/WSL 2 only. Hosted inference, package downloads,
Linux-host support and network access were not attempted. Next is S017's
bounded world-phenomena design note and implementation.
