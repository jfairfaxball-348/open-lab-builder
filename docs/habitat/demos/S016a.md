# S016a: save, find and reuse a procedural skill

This is a scripted engineering demonstration, not an autonomy experiment.
No local or hosted model inference was made. S016 was split before coding:
this session supplies procedural notes; executable tool registration is S016b.

## Implemented

Habitat **0.2.1**, 16 capabilities, content digest
`ca2ce18d975dd7b60a84bd0fd8d44e652884556e5187e1d2595980aee2a15f17`.
The release is built and published locally; its generated Simulation fixture
is copied from the Builder output, without manual editing. The earlier local
0.2.0 development build remains an unused immutable output; acceptance and
source use 0.2.1.

- `skills.save`: named procedure with title, summary, ordered steps, examples
  and optional tags. Duplicate ids require `replace=true`. Writes atomically
  to `.skills/<id>.json` in the workspace, with `provenance.origin: agent`.
- `skills.list`: case-insensitive AND substring search of id/title/summary/tags,
  sorted by id, with offset pagination. An empty query lists all notes.
- `skills.get`: full note or `exists=false` for an unknown id.

Discovery uses the existing capability search/describe/invoke interfaces;
saved notes themselves are found via `skills.list/get`. Notes are bounded to
100000 UTF-8 bytes, at most 1000 store entries and 50 summaries per list page.
They cannot grant permissions or register executable code. Malformed stored
data, unexpected store entries, directories and links are refused visibly.
Explicit replacement can repair malformed note data, but cannot follow links.
The workspace is agent-owned; its provenance label is not a tamper-proof
authorship attestation. Infrastructure preserves the actual calls and bytes.

## Preserved demonstration

Simulation configuration: `experiments/habitat/s016a-demo.json`.
Archive under the configured data root:
`runs/s016a-demo/run-20261116t092747z-952d44`.

1. Search for saving a reusable procedure and describe `skills.save`.
2. Save `sum-check`, including steps and an example.
3. Operator-pause at the third complete step and verify the archive.
4. Resume the same run from its protected checkpoint.
5. Find the note with the keyword `ARITHMETIC`, then retrieve its full steps.
6. Execute the pre-scripted sum procedure using `python.run`, producing stdout
   `10` with exit status 0, and read the saved result `10`.

Result: **completed**, 67 events, seven successful tool results, archive
verification passed. The event log before pause remains an exact prefix after
resume. Commands to reproduce from the Simulation checkout:

```text
uv run ols run experiments/habitat/s016a-demo.json --pause-after-steps 3
uv run ols verify <archive>
uv run ols resume <archive>
uv run ols verify <archive>
```

The live acceptance test additionally damages the live note after pausing and
checks that resume restores the protected original before finding and using
it. The script supplies all actions in advance; it does not establish that a
model independently learns, selects or follows a procedure.

## Validation and limits

Builder's 24 new tests cover round-trip/replacement, missing ids, deterministic
keyword pagination, invalid input with no effects, malformed/oversized stored
data, encoded-byte and entry limits, Windows junction refusal, hard links and
directory targets. All passed without skips. Every world capability self-test
passes; two builds have the same digest, and verification with self-tests passes.

Simulation's two new live container tests pass with
`OPEN_LAB_REQUIRE_CONTAINER=1`: pause/resume/reuse through the real supervisor,
and directory/file symlink refusal through the real container tool host.
An initial supervisor-level symlink probe terminated with
`resource_limit:monitoring`, because the existing quota monitor refuses links
before a later call. The capability refusal test therefore uses the container
tool host directly, without changing supervisor enforcement. An initial lint
check found import ordering and one long test line; both were fixed.

Full regression results are recorded in `docs/roadmap/state.json`.
Execution was on Windows/WSL 2 only. No schema, runtime, observer or sandbox
privilege changed. Procedures are data; executable tool validation, dynamic
registry integration and its checkpoint security checks remain S016b.
