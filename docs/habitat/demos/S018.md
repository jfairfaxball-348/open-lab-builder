# S018: bounded waking and data-only project continuation

This is scripted engineering acceptance, not an autonomy or cognitive-continuity
experiment. No model inference, hosted spending, model download or system
scheduler installation was used. The design is recorded in
[ADR-0025](../../decisions/ADR-0025-time-and-run-lineage.md).

## Delivered

Habitat **0.5.0**, 22 capabilities, content digest
`3a076c9c8ce2812d0d3fd4d5435faf723a1130a0bc7b64be3cfef6954e6f2639`.
Two builds have identical digests and all 22 self-tests pass; verification
passes. The two new Builder self-tests return explicitly unavailable fakes,
not invented budget values or real waits. The generated Simulation fixture is
copied from Builder output without manual editing.

`time.remaining` returns the original remaining active budget in milliseconds,
excluding operator pause and deadline grace. `time.sleep` schedules a bounded
relative active-time wake under `self-scheduled-v1`; other policies hide/refuse
it. Sleeping consumes budget. The supervisor rechecks recorded requests, keeps
private wake state in protected checkpoints, and admits no model-input preparation
while a sleep is pending. Waking injects no message. Same-turn calls after a
successful sleep request are refused. Existing deadline, step and resource caps
remain authoritative; no real-time wake guarantee is made.

Operator `ols run CONFIG --from-run ARCHIVE` creates a new run from a verified
completed source's protected final workspace/SQLite snapshots. It ignores the
live source workspace. Child lineage evidence is pinned in its launch event;
parent sidecars record child references without changing existing source logs,
summary or checkpoints. Each archive can be verified without its relatives.
Only file/memory data persist: conversation, budgets, model/permissions, private
field/wake state and trusted executable-tool registrations start fresh. Saved
tool source needs fresh validation in the child.

## Preserved demonstration

Configurations in Simulation:
`experiments/habitat/s018-parent-demo.json` and `s018-child-demo.json`.

Archives beneath the configured data root:

- `runs/s018-parent-demo/run-20261116t114910z-543f69`
- `runs/s018-child-demo/run-20261116t114919z-aacd68`

The parent discovers the time interface, saves `project.py` and a project memory,
reads remaining time and requests a two-second sleep. It is operator-paused after
step six, verified, held paused for one second and resumed. The wake target is
active elapsed time 3828 ms; the recorded wake occurs at 4701 ms. Barrier/I/O
scheduling can deliver a wake late; it never authorises early inference or an
extended budget. No model.call, agent.output or environment.message appears
between scheduling and wake. After waking, the parent computes and saves `10`.

The child was launched through the actual CLI `--from-run` route. It reads the
inherited program and result, retrieves `project/plan` from inherited memory,
uses the program in a new calculation and saves `60`. The original parent log
and summary remain byte-identical, and its child-reference sidecar exists.

Results: both **completed**. Parent: 79 events/eight successful tool results.
Child: 45 events/five successful tool results. Both archives verify, including
time ordering and portable lineage evidence. Parent pre-pause log bytes remain
an exact prefix after resume. These actions were scripted in advance; they do
not show a model independently planning or recognising an earlier self.

```text
uv run ols run experiments/habitat/s018-parent-demo.json --pause-after-steps 6
uv run ols verify <parent archive>
uv run ols resume <parent archive>
uv run ols run experiments/habitat/s018-child-demo.json --from-run <parent archive>
uv run ols verify <child archive>
```

The parent was run/resumed through the supervisor API; the child command above
was actually exercised via the CLI. Raw local CLI output is retained only in
ignored local scratch, not in this repository.

## Tests and limits

Eighteen new Simulation tests cover exact fake-clock budget/wake boundaries,
the checkpointed wake-ready acknowledgement latch, invalid/oversized/duplicate
sleep requests, policy/remaining-budget refusal, record-sync failure, private
state bounds, real sleep/pause/resume with paused downtime excluded, no inference
or injected messages during waiting, deadlines, same-turn refusal, journal
tampering, final-snapshot inheritance instead of edited live files, memory reuse,
fresh permissions/budget/field state, absent inherited trusted registrations,
portable verification, source-byte tampering and live/paused/corrupt/out-of-root/
missing-final-checkpoint refusal. A hostile worker test checks request binding,
duplicate refusal, early model-input denial and private wake-state forgery.

Seven new Builder tests check explicit unavailable fakes, complete available
outputs and invalid time data refusal before service access. A related
96-test policy/checkpoint/run regression subset also passed. Full regression
results are recorded in `docs/roadmap/state.json`.

Final review found that inherited artifacts were initially attributed to the
first child read tool. A system-owned scan before child execution now records
them before the first model call; a new assertion verifies that provenance. The
acceptance pair above was rerun after the fix. The earlier partial full regression
was interrupted at 53 percent and restarted against the corrected code; earlier
development archives are retained, not relabelled as final evidence.

Initial lint identified an unused import and several long source/test lines;
these were corrected. No failing behaviour assertion was weakened or skipped.
No new dependencies or shared schema changes were needed.

Only verified completed sources with a usable final complete-step checkpoint
are eligible. Failed imports can retain allocated staging, reported explicitly.
Lineage references are not signatures or independent chronology proofs; parent
sidecars do not attest child completion. Waking is active-time scheduling inside
a running supervisor, not an OS alarm across shutdowns. Native execution was
Windows/WSL 2 only. Long-duration overhead and physical power-loss recovery remain
unmeasured. Next is S019, Habitat v1 assembly; no hosted allowance is created.
